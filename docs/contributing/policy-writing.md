# Policy Writing Guide

업무 정책서는 [Documentation](documentation.md)의 공통 기준을 따른다. 현재 형식은 [User Policy](../policies/user.md)와 [Authentication Policy](../policies/authentication.md)를 참고한다.

업무 조건과 결과만 작성한다. table, field, Java type, JWT claim, Redis key와 framework 설정은 기술 문서나 코드에 둔다. 구현에서 새 정책을 추측하지 않는다.

## 문서 구조

대분류는 업무 영역으로 나눈다. 제목 아래에 링크 목차를 두고 본문도 같은 순서로 배치한다. 목적 영역은 두지 않는다.

```markdown
# Authentication Policy

## 목차

- [로그인](#로그인)
  - [인증 실패](#인증-실패)
- [인증 유지](#인증-유지)
  - [토큰 갱신](#토큰-갱신)

## 로그인

### 인증 실패

## 인증 유지

### 토큰 갱신
```

## 표현

- 각 영역은 독립적으로 읽을 수 있게 작성한다.
- 핵심 정책, 적용 조건과 예외, 필요한 예시 순서로 배치한다.
- 모든 참여자가 이해하는 업무 용어를 사용한다. field, enum과 역할 코드로 정책을 표현하지 않는다.
- 조건을 먼저 쓰고 허용, 제한과 결과를 명시한다. 경우의 수가 많으면 의사결정표를 사용한다.
- 미결정 사항은 상태 인용문 안에 `A vs B`로 적는다.

## 정책 적용 예시

복잡하거나 모호한 정책은 아래 형식으로 예시를 둔다.

````markdown
#### 적용 예시

```text
1. 등록되지 않은 이메일로 로그인 요청
   -> 계정 존재 여부를 노출하지 않는 인증 실패를 반환함

2. 사용한 refresh token을 다시 제출
   -> 같은 로그인에서 발급한 refresh session을 모두 폐기함
```
````

## 권한 정책

역할별 허용 여부를 비교해야 하면 관련 영역 앞부분에 권한 매트릭스를 둔다. 기본 권한만 `허용`과 `불가`로 표시하고 조건과 예외는 표 아래에 서술한다.

## 정책 상태

정책은 확정 여부와 반영 시점에 따라 다음 상태로 구분한다.

| 상태 | 정의 | 작성 형식 |
| --- | --- | --- |
| 정책 확정 | 결정이 완료되어 현재 적용하는 내용 | 관련 영역의 본문에 작성한다. |
| 논의 필요 | 현재 범위에서 결정해야 하는 내용 | 관련 영역 바로 아래에 `> 논의 필요`로 작성한다. |
| 추후 반영 예정 | 반영하기로 결정했지만 현재 범위에는 포함하지 않은 내용 | 관련 영역 바로 아래에 `> 추후 반영 예정`으로 작성한다. |
| 추후 검토 | 현재 범위 밖에서 도입 여부를 검토할 내용 | 관련 영역 바로 아래에 `> 추후 검토`로 작성한다. |

확정되지 않은 내용을 일반 정책과 섞지 않는다. 상태는 인용문 첫 줄에 고정 표제로 작성하고 다음 줄부터 내용을 작성한다.

```markdown
> 논의 필요
>
> 일반 로그인 세션을 하루 동안 유지함 vs browser 종료 시 만료함
```

## 다른 문서와의 경계

문서별 역할은 [Documentation](documentation.md#문서별-역할)을 따른다. 보안 프로토콜, token 검증, cookie와 암호화는 [Security](../operations/security.md)에 둔다.

정책과 구현의 차이는 보고하고 확정된 결정에 맞춰 갱신한다. 미확정 정책은 [AGENTS.md](../../AGENTS.md#문서에-없는-정책)를 따른다.
