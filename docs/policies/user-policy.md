## 사용자 계정

사용자는 변경되지 않는 내부 식별자로 구분합니다. 이메일이나 사용자 정보가 변경되어도 내부 식별자는 변경하지 않습니다.

### 계정 생성

현재 범위에서는 일반 로그인을 검증할 수 있도록 이메일과 비밀번호를 사용하는 계정 생성 흐름을 제공합니다.

> 논의 필요
>
> 공개 회원가입 API를 제공함 vs 개발 및 테스트용 계정 생성 경로만 제공함
>
> 계정 생성 전에 이메일 인증과 필수 약관 동의를 요구함 vs 현재 예제 범위에서 제외함

### 이메일

로그인에 사용하는 이메일은 올바른 형식이어야 하며 둘 이상의 사용자 계정이 같은 이메일을 사용할 수 없습니다.

이메일의 대소문자와 공백을 같은 주소로 판단하는 기준은 계정 생성과 로그인에서 일관되게 적용합니다.

> 논의 필요
>
> 이메일 원문과 정규화된 로그인 식별자를 함께 보관함 vs 정규화된 이메일만 보관함

### 비밀번호

비밀번호는 검증된 password hashing library로 단방향 변환해 저장합니다. 비밀번호 정책은 계정 생성과 비밀번호 변경에 동일하게 적용합니다.

> 논의 필요
>
> 비밀번호의 최소·최대 길이와 허용 문자
>
> 유출된 비밀번호 차단 여부

## 사용자 상태

서비스를 이용할 수 있는 사용자만 로그인하고 인증이 필요한 기능을 사용할 수 있습니다. 이용 제한, 탈퇴 대기와 삭제처럼 서비스 이용 가능 여부가 달라지는 상태는 사용자 context가 소유합니다.

> 논의 필요
>
> 최초 구현에 포함할 사용자 상태와 상태 전이

## 사용자 권한

새로 생성한 사용자는 일반 사용자 권한을 가집니다. 운영 권한은 회원가입 요청으로 선택하거나 획득할 수 없습니다.

> 논의 필요
>
> 운영 권한을 부여하고 회수하는 관리 경로

## 사용자 정보

인증에 필요한 정보와 사용자에게 표시되는 프로필 정보는 같은 의미로 취급하지 않습니다. access token에는 이메일, 닉네임과 같은 사용자 정보를 포함하지 않습니다.

> 추후 검토
>
> 닉네임, 프로필 이미지와 선호 언어

## 탈퇴와 재가입

> 추후 검토
>
> 탈퇴 대기 기간, 재가입 제한, 개인정보 삭제와 다른 context가 소유한 기록의 보관 기준
