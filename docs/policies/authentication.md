## 인증 수단

사용자는 등록한 이메일과 비밀번호로 로그인합니다. 소셜 로그인은 현재 범위에 포함하지 않습니다.

비밀번호 원문은 저장하거나 로그에 남기지 않습니다.

## 로그인

등록된 이메일과 비밀번호가 일치하고 활성 상태인 사용자만 로그인할 수 있습니다.

로그인에 성공하면 사용자의 인증 상태를 나타내는 단기 access token과 인증을 갱신할 수 있는 refresh token을 발급합니다. token 전달과 검증의 기술 기준은 [Security Policy](../operations/security.md)를 따릅니다.

### 인증 실패

이메일이 등록되지 않았거나 비밀번호가 일치하지 않으면 같은 인증 실패 결과를 반환합니다.

로그인 실패 시 입력한 비밀번호, 저장된 비밀번호 정보와 token을 로그에 남기지 않습니다.

### 이용이 제한된 사용자

이용 제한된 사용자가 올바른 이메일과 비밀번호로 로그인하면 일반 인증 실패와 구분되는 이용 제한 결과를 반환합니다. 로그인은 허용하지 않으며 제한 사유와 불필요한 계정 존재 정보는 노출하지 않습니다.

## 인증 유지

access token이 만료되기 전까지는 refresh session 저장소의 장애와 관계없이 인증이 필요한 기능을 사용할 수 있습니다.

refresh session을 확인할 수 없거나 안전하게 갱신할 수 없으면 새로운 token을 발급하지 않습니다.

access token은 발급 시점부터 15분 동안 유효합니다.

### 자동 로그인

refresh session 만료는 최초 로그인 시점으로 고정하며 token 갱신으로 연장하지 않습니다.

| 자동 로그인 | 유지 기간 |
| --- | --- |
| 선택 | 최초 로그인부터 30일 |
| 미선택 | 최초 로그인부터 14일 |

### 토큰 갱신

아래 조건에 따라 token을 갱신합니다.

#### 적용 예시

```text
1. 유효한 refresh token으로 갱신을 요청합니다.
   -> 기존 token을 소비하고 새 access token과 refresh token을 발급합니다.

2. 이미 소비한 refresh token으로 다시 갱신을 요청합니다.
   -> token 재사용으로 판단하고 같은 로그인에서 파생된 refresh session을 모두 폐기합니다.

3. 같은 refresh token으로 두 요청을 동시에 보냅니다.
   -> 하나만 성공하며 다른 요청은 같은 token으로 갱신에 성공하지 못합니다.
```

## 로그아웃

로그아웃하면 현재 refresh session을 폐기하고 browser에 저장된 인증 cookie를 만료시킵니다. 이미 발급된 access token은 별도의 차단 목록을 두지 않으며 남은 유효 기간이 지나면 만료됩니다.
