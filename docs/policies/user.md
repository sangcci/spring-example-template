## 사용자 계정

사용자는 변경되지 않는 내부 식별자로 구분합니다. 이메일이나 사용자 정보가 변경되어도 내부 식별자는 변경하지 않습니다.

### 계정 생성

사용자는 이메일과 비밀번호로 공개 회원가입을 할 수 있습니다. 회원가입이 성공하면 일반 사용자 권한을 부여하고 로그인 상태를 시작합니다.

> 추후 반영 예정
>
> 계정 생성 전에 이메일 인증과 필수 약관 동의를 요구합니다.

### 이메일

로그인에 사용하는 이메일은 올바른 형식이어야 하며 둘 이상의 사용자 계정이 같은 이메일을 사용할 수 없습니다. 이미 가입된 이메일로 회원가입을 요청하면 이미 가입된 이메일임을 반환합니다.

계정 생성과 로그인은 아래 이메일 정규화를 적용합니다.

#### 적용 예시

```text
1. " User@Example.com "으로 회원가입 요청
   -> "user@example.com"으로 정규화해 저장합니다.

2. 저장된 "user@example.com" 계정에 " USER@example.com "으로 로그인 요청
   -> 같은 정규화 기준으로 계정을 찾습니다.
```

현재 이메일은 ASCII 형식을 사용합니다. local part는 64자 이하이고 점으로 시작하거나 끝날 수 없으며 연속된 점을 허용하지 않습니다. domain은 점으로 구분된 둘 이상의 label로 구성하고 각 label은 영문 소문자, 숫자와 중간의 하이픈만 허용합니다. 전체 이메일은 320자 이하여야 합니다.

### 비밀번호

비밀번호는 검증된 password hashing library로 단방향 변환해 저장합니다. 비밀번호 정책은 계정 생성과 비밀번호 변경에 동일하게 적용합니다.

비밀번호는 8자 이상 16자 이하이며, 영문 대문자, 영문 소문자, 숫자, 특수문자를 각각 하나 이상 포함해야 합니다. 비밀번호에는 공백을 포함할 수 없습니다.

> 추후 검토
>
> 유출된 비밀번호 목록을 확인해 가입과 비밀번호 변경을 차단합니다.

### 비밀번호 변경

현재 비밀번호 확인이 성공한 사용자만 비밀번호를 변경할 수 있습니다. 비밀번호 변경이 성공하면 해당 계정의 모든 인증 갱신 수단을 폐기하고, 현재 browser의 인증 cookie도 만료시킵니다. 사용자는 새 비밀번호로 다시 로그인해야 합니다.

## 사용자 상태

사용자 상태는 활성, 이용 제한, 탈퇴로 구분합니다. 서비스 이용이 가능한 활성 사용자만 로그인하고 인증이 필요한 기능을 사용할 수 있습니다. 이용 제한과 탈퇴처럼 서비스 이용 가능 여부가 달라지는 상태는 user context가 소유합니다.

이용 제한 사유는 500자 이하로 보관합니다.

| 제한 종료 시각 | 처리 |
| --- | --- |
| 있음 | 해당 시각에 활성 상태로 전환 |
| 없음 | 영구 제한 |

이용 제한된 사용자는 로그인할 수 없으며 일반 인증 실패와 구분되는 이용 제한 결과를 받습니다. 이용 제한을 처리하면 해당 계정의 모든 인증 갱신 수단을 폐기합니다.

> 추후 반영 예정
>
> 운영자가 이용 제한을 부여하거나 해제하는 기능을 제공합니다.

## 사용자 권한

역할은 일반 사용자와 운영자로 구분합니다. 가입 시 일반 사용자 권한을 부여하며 운영 권한은 선택하거나 획득할 수 없습니다.

> 추후 반영 예정
>
> 운영 권한을 부여하고 회수하는 관리 경로를 제공합니다.

## 탈퇴와 재가입

현재 비밀번호 확인이 성공한 사용자만 탈퇴할 수 있습니다. 탈퇴를 처리하면 해당 계정의 모든 인증 갱신 수단을 폐기합니다.

| 항목 | 기준 |
| --- | --- |
| 계정 보관 | 탈퇴 시점부터 30일 |
| 정리 시각 | 매일 `Asia/Seoul` 오전 3시 |
| 삭제 | 30일이 지난 `user_account` 행을 조건부 삭제하며 정확히 30일인 시점도 포함 |
| 삭제 정보 | 이메일, 비밀번호 hash 등 계정 식별 정보. 익명화된 사용자 행은 남기지 않음 |
| 재가입 | 탈퇴 시점부터 7일 동안 같은 이메일 사용 불가 |

> 추후 검토
>
> 다른 context가 소유한 기록의 보관 기준을 정합니다.
